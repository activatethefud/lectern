# AGENTS.md

Conventions for anyone (human or agent) changing this repo. Read this before editing.

## What this is

A Nuxt 4 app. **A course is a folder**, not a database row: `courses/<slug>/` holds the deck, its
questions, and its baked slide images. The server reads that folder at request time, so adding a
course never requires an app rebuild.

```
courses/<slug>/
  course.json      # title, description, tags, lang, optional passThreshold/order
  questions.json   # one entry per slide; every string may be {sr, en, zh-CN}
  slides.pptx      # the course itself, in `lang`
  slides.en.pptx   # GENERATED by tools/translate-deck.mjs — commit
  translation/en.json   # extracted runs + translations (source of the deck above) — commit
  manifest.json    # GENERATED by `npm run bake`: variants sr/en/zh-CN — commit
  slides/00N.jpg            # GENERATED — base deck
  slides/en/00N.jpg         # GENERATED — translated deck
```

## Commands

| | |
|---|---|
| `./serve` | dev server on 127.0.0.1:8765 (inside `nix develop`) |
| `./test` | `vitest run` — unit + `@nuxt/test-utils` integration |
| `npm run bake` | pptx → pdf → jpg for every course (needs libreoffice + poppler) |
| `npm run bake:check` | fails if `manifest.deckSha` ≠ sha256 of `slides.pptx` |
| `npm run build && npm start` | production node server on `.output/server/index.mjs` |
| `npm run typecheck` | `vue-tsc` over app + server |
| `docker compose up -d --build` | container on 127.0.0.1:8765, data in the `course-data` volume |
| `docker compose run --rm bake` | re-bake decks inside a container (LibreOffice stays out of the runtime image) |

Runtime images are **Node only** on purpose — if you find yourself adding `libreoffice`,
`poppler` or a native module to the `runtime` stage of the Dockerfile, the design is being broken.
Env for containers: `NUXT_COURSE_ROOT`, `NUXT_DATA_DIR` (Nitro reads `NUXT_`-prefixed env at runtime;
plain `COURSE_ROOT`/`DATA_DIR` only feed the dev shell).

## Invariants — do not break these

1. **Answers never reach the client before the report.** `questions.json.answer` and `.why` stay
   server-side. No API payload, SSR HTML comment, or serialized Nuxt state may contain them.
   `tests/leak.test.ts` enforces this; extend it, never weaken it.
2. **`why` is revealed only on the report page of a *passed* attempt.** Failed attempts show which
   slides were wrong, never the correct option or the explanation.
3. **Answers are editable until the attempt is finished.** `POST /api/c/[slug]/answer` upserts —
   the last click wins — and nothing is graded before the report is generated. Once the report has
   been generated the attempt is closed and further answers are rejected with `409`; the learner
   starts a retake instead (`POST /restart`). GETs must never create or mutate an attempt.
4. **Scoring is server-side**, from the DB, never from a client-supplied score.
5. **Baked images are committed.** If you edit a `slides.pptx`, run `npm run bake <slug>` and commit
   the resulting `slides/*.jpg` + `manifest.json` in the same commit. CI runs `bake:check`.
   Translated decks are pipeline output too: `translation/<lang>.json` → `slides.<lang>.pptx` →
   `slides/<lang>/*.jpg`. Never hand-edit a translated `.pptx`; re-run extract/apply.
6. **A course folder is self-contained.** No per-course code, no per-course config outside the folder.
7. **Route URLs are stable** — they appear on printed certificates. Never rename `/c/<slug>` or
   `/verify/<id>`; keep `/verify/<id>` outside the i18n prefix.
8. **i18n:** every user-visible string goes through `t('key')`, with the key present in *all three*
   files in `i18n/locales/` (`sr`, `en`, `zh-CN`). Course content strings may be
   `"text"` or `{"sr": …, "en": …, "zh-CN": …}` — resolve with `pickLocalized()` from `shared/course.ts`.
9. **Slug format** is `^[a-z0-9][a-z0-9-]{0,63}$`; it is part of the URL and the certificate ID input.
10. **Certificates are issued once and bound to their holder.** `serial` (`SC-YYYY-NNNNNN`) is public
    and sequential; `verifyId` is random and only the owning `sid` may download `/certificate/<verifyId>`
    (404 for anyone else); `signature` is an HMAC over the printed fields and `/verify` recomputes it.
    Never expose a `verifyId` on a public page, never regenerate a serial, never let a name change
    after issue.
11. **No new runtime dependency** without a note in `PLAN.md` §11. The stack is deliberately small:
    nuxt, @nuxtjs/i18n, pdf-lib, @pdf-lib/fontkit. No ORM, no UI kit, no CSS framework.

## Layout

```
app/            pages (route = path), layouts, components, assets/css
  pages/index.vue            catalogue + search
  pages/c/[slug]/index.vue   cover: start / resume / restart / download per language
  pages/c/[slug]/[n].vue     player: slide + question, answers locked, SR/EN/中文 switch
  pages/c/[slug]/report.vue  score, red/green per answer, name gate → certificate
  pages/verify/[id].vue      public certificate check (locale-free)
server/
  api/courses.get.ts         catalogue JSON
  api/health.get.ts          docker healthcheck
  api/c/[slug]/index.get.ts        cover payload (+ nextSlide)
  api/c/[slug]/slide/[n].get.ts    player payload, strips answer/why, picks deck by ?lang
  api/c/[slug]/answer.post.ts      records one final answer (409 on retry)
  api/c/[slug]/restart.post.ts     drops the open attempt
  api/c/[slug]/report.get.ts       finalizes + per-item correct flags, `why` only on pass
  api/c/[slug]/certificate.post.ts name → cert id
  api/verify/[id].get.ts           public check by serial or verify id
  routes/certificate/[id].get.ts   PDF — owner session only
  utils/certauth.ts                serial, verify id, HMAC signature
  routes/c/[slug]/slide/[n].get.ts jpg stream (?lang=), immutable cache
  routes/c/[slug]/slides.pptx.get.ts   download (?lang=), Content-Disposition: attachment
  routes/certificate/[id].get.ts   pdfkit PDF by certificate id
  utils/courses.ts           folder discovery, validation, variantFor()
  utils/questions.ts         questions.json schema validation + localization
  utils/store.ts             sqlite attempts/answers (node:sqlite), sid cookie
  utils/grading.ts           score, pass mark, certificate id
  utils/certificate.ts       pdfkit rendering (fonts in server/assets/fonts)
shared/course.ts             types + fold()/matchesQuery()/pickLocalized() (client & server)
scripts/bake-courses.mjs     pptx → jpg everywhere, manifest variants, bake:check
tools/translate-deck.mjs     extract / apply translated decks (layout-preserving)
tests/                       search.test.ts (unit), api.test.ts (Nuxt integration), e2e/ (M6)
```

## Style

- TypeScript everywhere, strict. Server code has no `any`; use types from `shared/course.ts`.
- Small files, one responsibility. `utils/` functions take plain data, so they are unit-testable
  without a server.
- No client-side answer checking, no `v-html` with content, no inline event handler strings.
- Comments explain *why*, not *what*. Delete rather than comment out.
- Commits: `<area>: <what>` (`bake:`, `player:`, `i18n:`, `store:`, `test:`). Never commit `data/`.
